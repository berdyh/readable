Chat Bot Update Notes

Running notes for chatbot behavior, UI decisions, spec interpretation, and follow-up questions.

2026-05-25 Chatbot Repair Pass

The chatbot work builds on the Clerk-user data isolation branch. The chat APIs are authenticated and persisted through Postgres, so the UI must make signed-in state explicit instead of allowing anonymous requests that fail later.

Design Decisions

  • Treat the block-editor side panel as the primary chatbot surface because it owns saved sessions, tabbed history, source navigation, and editor insertion.
  • Keep the inline chat block as a lighter embedded surface that writes answers back into the block content rather than duplicating session tabs.
  • Make the chatbot authenticated-only in the UI to match the server routes that now derive the user from Clerk.
  • Treat the tab delete control as session deletion because the existing API exposes DELETE /api/chat/history rather than a hide/archive state.
  • Keep a tab visible if session deletion fails, and disable new-chat/tab-delete controls while an answer is being saved so the active session cannot be removed mid-request.
  • Insert assistant answers into the editor only when the user clicks Insert answer; successful answers are no longer auto-inserted.

Deviations

  • The unfinished @ mention flow is not being kept as a pseudo-context picker. It currently turns arbitrary typed text into a selection payload, which is misleading.
  • The side panel now shows selected PDF text as explicit context instead of using the removed mention query state.

Tradeoffs

  • I am prioritizing a reliable saved-chat flow over anonymous temporary chat. Guest mode can be added later, but it needs a separate persistence and account-merge policy.
  • Failed assistant answers remain local error messages when the answer request fails after a user message is saved. Persisting failures would make history more complete, but it risks storing transient provider or quota errors as durable chat content.

Open Questions

  • Confirm whether closed chat tabs should permanently delete their saved session, or only hide it from the current panel.
