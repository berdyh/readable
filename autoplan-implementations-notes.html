Design Decisions

  • The controller owns the core QA/search response contract locally, because UI and persistence tasks depend on that server shape.
  • Answer trust states are intentionally small for this pass: sourced, uncited, and refused. Retrieval degradation is represented as metadata on the result rather than as a separate answer enum.
  • A citation is considered valid only when its chunk ID resolves to the current evidence loaded for the question. Unknown model-supplied chunk IDs are dropped and counted in trust metadata.
  • AnswerCard was extracted into src/app/components/ai-chatbot/answer-card.tsx so ChatIntegration and the older embedded ChatPanel render the same trust/provenance/source UI.
  • Chat-side UI state keeps the ergonomic message.trust field, but history persistence serializes the same data as versioned message.metadata for the API contract.

Deviations

  • The approved plan listed duplicate task IDs across phases. This implementation groups them by subsystem instead of following task IDs literally.
  • The QA contract does not fabricate a replacement source for uncited answers. It returns an empty cites array with trust.status = "uncited" when evidence exists but the model did not provide a valid citation.
  • The approved plan named a broader answer union including degraded_text_only, source_unavailable, and error. This implementation keeps the backend answer enum smaller and represents degradation/source availability as metadata and row-level UI state.

Tradeoffs

  • Subagents are running with disjoint write scopes. This gives parallel progress but means the controller will do final integration and cross-file type cleanup.
  • Provider errors from /api/qa are mapped to stable safe codes and messages. Raw provider error text stays in server logs only.
  • pnpm verify intentionally excludes live store, embedding, Clerk, arXiv, and LLM checks. Those remain explicit commands so a clean contributor proof is deterministic.
  • Legacy assistant messages without metadata are marked trust.status = "unavailable" at the API edge instead of backfilling inferred trust.

Metrics And Kill Criteria

  • /api/qa emits a privacy-safe [qa] trust_counter log with trust status, citation counts, retrieval status, and hit counts only. It intentionally excludes paper IDs, user IDs, questions, answers, quotes, selected text, and source text.
  • Source navigation emits a browser-only readable-source-proof-counter event with action, status, source type, page presence, and source count only.
  • Day-1 sidecar review should track trust-state mix, uncited/refused rate, retrieval degradation rate, source-click success/unavailable rate, and repeat use after saved-history reloads.
  • Sidecar direction remains viable if sourced answers dominate answered QA sessions, source-click unavailable states stay rare, and the documented local proof loop stays under 10 minutes. If uncited or unavailable states are common, revisit the evidence-dossier direction before expanding the chat surface.
  • Owner: branch implementer until handoff. Review date: 2026-07-16 or after the first 20 authenticated QA sessions, whichever comes first.
