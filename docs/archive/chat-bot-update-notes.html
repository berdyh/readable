2026-06-15 /autoplan Working Brief

This review uses the approved office-hours design document as the source of truth: /home/shoh/.gstack/projects/berdyh-readable/shoh-feat-chat-panel-resizer-design-20260615-214149.md. The selected direction is the trust-first reader chat sidecar, not a resizer-only polish slice.

Approved Premises

  • Source-grounded reader/chat UX is the core product value. Layout and resizing only matter when they make grounded reading easier.
  • The QA layer must return an explicit trust state: sourced, degraded_text_only, uncited, source_unavailable, refused, or error.
  • Answers must not appear fully sourced unless at least one current, navigable citation can take the user back to a rendered chunk, figure, or PDF page.
  • Vector or embedding failure must degrade visibly to text-only retrieval instead of becoming an empty-result path that looks like weak paper evidence.
  • Public arXiv text remains read-only, while summaries, saved chats, skill state, and durable personalized routes stay Clerk-gated.
  • Local coding-agent mode remains an isolated prompt-response LLM backend with Codex-only defaults unless an explicit unsafe or custom local opt-in is present.
  • Same-paper ingest replacement must serialize DB replacement and post-commit vector replacement so stale chunks cannot look current after re-ingest.

Answer Card Anatomy

  1. Trust strip: a one-line status above every assistant answer. It shows a text label, an icon, source count, retrieval mode, and a short reason. It is always visible; source details expand below it.
  2. Answer body: the assistant response. It never carries source styling unless the trust strip says the answer is sourced or degraded with evidence.
  3. Provenance strip: compact default row, for example 3 sources - hybrid retrieval - all navigable. This is the chosen default, replacing the previous ambiguous "visible by default or summarized" decision.
  4. Source details: expandable rows under the answer. Each row shows chunk/page/figure id, quote preview, navigation status, and a button label such as Open chunk, Open page, Open figure, or Source unavailable.
  5. Recovery action: degraded, uncited, refused, unavailable, and error states include a next action: retry, ask with selected text, open paper page, or sign in.

Proof Moment Flow

User asks question
  -> sidecar shows "Finding evidence"
  -> answer appears with trust strip
  -> provenance strip shows source count and retrieval mode

  -> if no target exists, source row stays expanded with unavailable reason

Responsive and Accessibility Requirements

  • Desktop: reader and chat remain side-by-side. The provenance strip stays directly below the answer, not in the hidden right rail.
  • Mobile: reader stacks above chat. Expanded source rows stay inside the chat flow; source clicks scroll the reader target into view and return focus to the source row if no target is found.
  • Source rows, trust strip controls, retry buttons, and sign-in actions must have at least 44px touch targets.
  • Trust states must not rely on color alone. Use label text plus icon. Warning and error colors must meet body-text contrast.
  • Loading, degraded, refused, unavailable, and error status changes use appropriate aria-live announcements.
  • Keyboard order: input -> answer actions -> provenance strip -> source rows -> insert answer. Source click success moves focus to the highlighted reader block when possible.
